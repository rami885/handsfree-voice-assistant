تاريخ البدء: 2026-11-09؛ تحديث الحالة: 2026-11-10. الفرع: `codex/m0-skeleton`، الأساس: `main`. هذا التقرير يصلح وصفاً لطلب السحب المسودة الذي سيفتحه Claude وفق تعليمات الحاوية.

## الإصدارات المثبتة

AGP 9.5.1، Gradle 9.6.0، Kotlin 2.4.21، KSP 2.3.13، Hilt 2.60.1، Coroutines 1.11.0، Room 2.8.5، Kover 0.9.11، JUnit 4.13.2، AndroidX Test Runner 1.7.0، Espresso 3.7.0. التفاصيل وسبب الاختيار في [مصفوفة البناء](build-matrix.md). Node الموجود في الحاوية 22.23.4 وnpm 10.9.9؛ لا وسيط في M0.

## أوامر التشغيل

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export GRADLE_USER_HOME="$PWD/.cache/gradle"
export TMPDIR="$PWD/.cache/tmp"
export ANDROID_USER_HOME="$PWD/.cache/android"
mkdir -p "$TMPDIR"
./gradlew build test lint
python3 scripts/check-safety.py
```

## قرارات اتخذتها

- بدأت محاولة M0 بـ AGP 8.10.1 وGradle 8.14.3 وKotlin 2.1.20 وKSP 2.1.20-2.0.1 وHilt 2.56.2. أثبت lint أن هذه المصفوفة تفشل فحوص تحديث الاعتماديات مع warningsAsErrors. انتقلت قبل تثبيت M0 إلى AGP 9.5.1 وGradle 9.6.0 وKotlin المدمج، مع تحديث المكتبات المبينة أعلاه وإضافة dataExtractionRules. لم أُعطّل قاعدة lint أو أخفض شدتها. هذه كانت مصفوفة أولية قبل تثبيت M0؛ المصفوفة الحالية تستخدم AGP 9 وفق نموذج Kotlin المدمج. تصحيح تفسيري السابق للتحذيرات موضح أدناه.
- واجهات core/assist هياكل غير مسجلة في manifest المنتج بعد، وخدمة التعرف فيه ترفض الطلب بوضوح؛ الوكيل الفعلي للتجارب يُنفذ في M3. البديل إضافة سلوك منتج الآن يتجاوز نطاق الهياكل.
- لا Compose قبل وجود شاشة إعداد ضمن النطاق. شاشات التجارب تشخيصية وليست إعداد المنتج النهائي.
- يبدأ backend.yml بفحص الأسرار فقط؛ تضاف أوامر Node واختبارات الوسيط مع كوده في M5، بلا مهمة اختبار معطّلة.
- استخدام JDK 17 المثبت بدلاً من JAVA_HOME الافتراضي الذي يشير إلى JDK 21. كاش Gradle والملفات المؤقتة داخل المستودع، ولم تُثبت حزم نظام.
- تشغيل CI عند دفع كل فرع إضافة إلى طلب السحب، لأن تعليمات الحاوية تؤجل فتح الطلبات إلى Claude.

## ما لم يُنفذ والتعارضات

لم تُبن أدوات تنفيذ ولا تخطيط شبكي ولا نشر. لا تعديل للوثائق المحمية، ولم تُستشر v12 أو draft4 لأن الملف حاسم في M0. لا تعارض مستجد معهما مثبت في هذا المعلم.

تعذر تنزيل checksum الاختياري لتوزيعة Gradle من مساري services.gradle.org وdownloads.gradle.org بسبب HTTP 403، وواجهة versions/9.6.0 أعادت 404. لم يُخترع checksum؛ التوزيعة نفسها نُزلت وشُغّل Wrapper. هذا لا يعطل اختبار البناء.

كل سلوك Android، بما فيه صلاحية أخذ دور المساعد وتشغيل الخدمات على الأجهزة، بتاريخ 2026-11-09: «يُثبت ميدانياً». لم تُجر تجربة جهاز أو محاكي في الحاوية.

## حادثة حدود الملفات

أثناء بناء M0 أنشأ AGP تلقائياً مفتاح توقيع debug في `/root/.android/debug.keystore` خارج المستودع (وقت ظهوره 21:54 UTC). هذا خروج عن قيد المستخدم بسبب المسار الافتراضي لأداة البناء، ولا أصفه التزاماً صحيحاً بالقيد. لم ألمس الملف لاحقاً. ضُبط `ANDROID_USER_HOME` داخل المستودع لجميع المحاولات اللاحقة. مفتاح debug ليس مفتاح API، ولم يُلتزم في Git.

## نتيجة التحقق عند الدفع

- `python3 scripts/check-safety.py`: نجح، بلا طباعة محتوى أسرار.
- `git diff --check`: نجح.
- `./gradlew build test lint`: لم ينجح حتى آخر محاولة؛ العائق الحالي HTTP 429 من Maven Central، لا نتيجة اختبار مختلقة. لم يُعطّل أي اختبار أو فحص.
- لا وحدات اختبارات منطق في M0؛ تُضاف اختبارات الحارس ابتداءً من M1.
- أُعيد تشغيل الحاوية مرتين؛ فُحصت الملفات والسجلات واستُؤنف الكاش، دون إعادة إنشاء الهيكل.
- لا يمكن اعتماد M0 نهائياً أو بدء M1 قبل نجاح CI حسب القسم 9.4 من الملف. سيحمل التقرير الليلي نتيجة GitHub الفعلية والمرجع.

## إصلاح تهيئة GitHub Actions

أول [تشغيل Android](https://github.com/rami885/handsfree-voice-assistant/actions/runs/42730557510) فشل قبل Gradle لأن القيمة الافتراضية لإجراء setup-android تطلب حزمة SDK القديمة `tools` التي لم يجدها sdkmanager. ضُبطت قائمة الحزم صراحةً إلى platform-tools وplatforms;android-36 وbuild-tools;36.0.0 بدلاً من القيمة الافتراضية، دون تخطي التهيئة أو الاختبارات. [تشغيل Backend الأول](https://github.com/rami885/handsfree-voice-assistant/actions/runs/42730557505) نجح؛ هذا فحص أسرار فقط في M0، ولا يعني اختبار وسيط لم يُبن بعد.

بعد إعادة تشغيل الحاوية الثانية تغيّر وكيل الشبكة، وأعاد فحص رابط الاعتماد الذي كان محجوباً HTTP 200. لذلك استؤنف البناء بمحاولة 10 بسبب تغيّر الحالة الخارجية، من دون مسح الكاش أو إعادة إنشاء العمل. نتيجتها تُسجّل بعد انتهاء الأمر.

## قرارات اتخذتها: شدة lint الافتراضية وSDK الملزم

وصلت المحاولة 11 إلى lint، وانتهى عائق تنزيل Groovy. الفشلان المتبقيان هما OldTargetApi وGradleDependency لأن SDK 37 أحدث من SDK 36 الملزم في الملف. سبب تحويلهما إلى خطأ هو `warningsAsErrors=true` الذي أضفته أنا، ولم يطلبه الملف. أزلت التصعيد العالمي الذي أضفته، وأبقيت `abortOnError=true` وكل قواعد lint بشدتها الأصلية، بلا disable أو ignore أو baseline أو تعديل شدة قاعدة مفردة. ستظل توصية SDK 37 ظاهرة كتحذير، بينما تظل أخطاء lint وفحوص الأذونات المحظورة مانعة للبناء. البديل تغيير SDK إلى 37 يخالف المصدر الملزم، وتعطيل القاعدتين يخالف قواعد المستخدم؛ لم أفعلهما. هذا تصحيح لإعداد أولي زائد، وليس ادعاء أن SDK 36 أحدث إصدار. يجب على المراجعين التحقق من هذا القرار.

## نتيجة محلية نهائية

المحاولة 12: `./gradlew build test lint` نجح خلال 8 ثوانٍ، 359 مهمة (84 منفذة و275 من الكاش)، JDK 17. لم توجد اختبارات منطق في M0؛ `NO-SOURCE` من Gradle لا يعني تعطيل اختبار. تقارير lint أُنتجت في app وprobes والوحدتين Android؛ توصيات SDK 37 باقية ظاهرة بشدتها الافتراضية. يُنتظر CI للالتزام الذي يحمل إصلاح الإعداد، ولا يبدأ M1 قبله.
