## الإصدارات والأوامر

المصفوفة لم تتغير عن M0: AGP 9.5.1، Gradle 9.6.0، Kotlin 2.4.21، KSP 2.3.13، Hilt 2.60.1، Coroutines 1.11.0، Room 2.8.5، Kover 0.9.11، JUnit 4.13.2، AndroidX Test Runner 1.7.0، Espresso 3.7.0. Node الحاوية 22.23.4 وnpm 10.9.9؛ لا وسيط بعد.

## قرارات اتخذتها

- غياب مصدر الأداة أو أي حقل يحدد المستلم يُرفض، بدلاً من افتراض أن المصدر موثوق. يشمل ذلك recipientLabel وconversationTarget كي لا تمر تعليمات مجموعة كبيانات شكلية.
- الاقتباس غير الموثوق مسموح في PERSONAL_READ فقط؛ لا يعاد توظيفه كنص إرسال أو مستلم أو أداة، وفق قيد الملف.
- كل SEND وCALL_OUT يحتاج تأكيداً حتى إن أخطأ تعريف الأداة وجعل sensitivity=NONE؛ الأفعال المحظورة تبقى مرفوضة أيضاً عند خطأ وسمها.
- نص التأكيد يذكر الفعل والمستلم والمحتوى والوجهة المتاحة؛ اللقطة الكاملة تربط بقية الحقول ومنها الاشتراك وفعل RemoteInput. لا يسجّل السجل هذا النص.
- خريطة المصادر تُنسخ إلى خريطة غير قابلة للتعديل، لأن val وحده لا يمنع تعديل خريطة قدمها المستدعي بعد التأكيد.
- لا تُلغى عملية بدأت Executing بأثر رجعي؛ cancel ينجح قبلها فقط كما يطلب الملف. يحتاج الربط الإنتاجي لاحقاً إيقاف المهام التي يمكن إيقافها عند Stop أو قفل الشاشة. لا توجد أداة إنتاجية هنا.
- سجل التدقيق ملف محلي بسيط بمخطط ثابت من بيانات القرار؛ أسماء الأدوات معرفات ثابتة لا تقبل أرقاماً. السبب رمز محدد، وليس رسالة استثناء أو نصاً من المستخدم. البديل Room داخل الحارس يخالف كونه وحدة JVM خالصة.

## العوائق وما لم يُنفذ

واجهت المحاولات 1 و2 و3 HTTP 429 لتنزيل hamcrest-core:1.3 (GET ثم HEAD). نُزّل الملف نفسه بواسطة curl من Maven Central وقورن SHA-1 بقيمة النشر الرسمية؛ تطابقت القيم. وُضعت النسخة المطابقة في كاش Gradle داخل المستودع، لكن Gradle ظل يطلب HEAD وأعاد 429. محاولة offline لم تجد فهرسة الأثر في الكاش وفشلت بوضوح؛ لم تُعد نجاحاً ولم يُستبدل Hamcrest أو تُحذف اعتمادياته. تُجرى إعادة المحاولة الثالثة بعد فاصل 40 ثانية، ثم يُعتمد توثيق العائق ونتيجة CI الفعلية.

لا أدوات إنتاجية، ولا تكامل Android للحارس في هذا المعلم. لم تُعدّل الوثائق المحمية. لم يلزم الرجوع إلى v12 أو draft4؛ لا تعارض جديد مثبت معهما. اختبار سلوك Android على الأجهزة خارج هذا المعلم، وكل ادعاء عنه بتاريخ 2026-11-10 «يُثبت ميدانياً».

## النتيجة المحلية النهائية

نجحت المحاولة 4 بعد فاصل 40 ثانية: `./gradlew build test lint :core:guard:koverVerify :core:guard:koverXmlReport` خلال 7 ثوانٍ. نفذ JUnit عدد 11 اختباراً في GuardTest و3 في GuardTaskTest، بصفر failures/errors/skipped. تقرير Kover: 118 سطراً مغطى وسطر واحد غير مغطى (99.16%)، دون أي مرشح أو استثناء للتغطية، واجتازت بوابة 90%. انتهى عائق Hamcrest؛ لا اعتماد مفقود باقٍ في هذا المعلم.

تقارير التحقق: `core/guard/build/test-results/test/` و`core/guard/build/reports/kover/report.xml`. فحص الأسرار والتصريحات المحظورة و`git diff --check` ناجحان. نتيجة GitHub Actions معلقة عند الدفع، وتُسجّل عند وصولها قبل بدء M2.

## إصلاحات المراجعة 2026-11-10

- **1-1 — تم:** غياب مصدر محتوى الإرسال أصبح رفضاً، وكذلك المصدر غير الموثوق، مع فحص مصدر الشريحة وحالة المستلم المحفوظ عند وجودهما. يبقى الاقتباس غير الموثوق مقبولاً للقراءة فقط. عُدّلت لقطة اختبار التأكيد لقبول مصادر صريحة. اختبار `sendingRequiresExplicitTrustedParameterOrigins` فشل قبل الإصلاح ويغطي الغياب والمصدر غير الموثوق حتى مع تأكيد سابق.
- **1-2 — تم:** أُضيف مفتاح الإشعار ومعرّف فعل الرد إلى حقول الوجهة؛ يرفض غياب مصدرهما أو عدم موثوقيته قبل التأكيد. اختبار `replyRoutingRequiresTrustedOrigins` فشل قبل الإصلاح ويغطي الحالتين لكل حقل.
- **1-3 — تم:** أصبح `ToolSpec.kind` حقلاً إلزامياً في التعريف الموثوق. يرفض الحارس أي تعارض مع اللقطة، وتستعمل جميع سياسات القفل والاستماع والتأكيد التصنيف الموجود في التعريف. اختبار `actionCannotOverrideTrustedToolKind` أثبت سماح القراءة المصنفة خطأً كفعل بلا بيانات قبل الإصلاح، ثم رفضها؛ مصفوفة القفل والاستماع بقيت مغطاة بتعريفات صريحة. يلزم تمرير التصنيف عند إنشاء كل تعريف أداة في الفروع اللاحقة.
- **1-4 — تم:** يذكر التأكيد الاسم والرقم الفعلي معاً حين يتوفران للاتصال والإرسال، وتظل اللقطة مرتبطة بالرقم. اختبار `confirmationSpeaksBothNameAndActualNumber` فشل سابقاً ويغطي الفعلين وتبديل الرقم بعد التأكيد. النطق الفعلي على Android «يُثبت ميدانياً» (2026-11-10).
- **1-5 — تم:** استُبدلت `Files.writeString` بـ `Files.write(byte[])` مع UTF-8 وخياري الإنشاء والإلحاق. اختبار `auditBytecodeDoesNotReferenceUnavailableAndroidWriteString` فشل قبل الإصلاح ويتحقق من غياب الإحالة غير المتاحة من الصنف المترجم، ويغطي `localAuditPersistsOnlyMetadata` الإنشاء والإلحاق الفعليين. تحقق توثيقي بتاريخ 2026-11-10: [Files.write متاحة منذ API 26](https://developer.android.com/reference/java/nio/file/Files#write(java.nio.file.Path,%20byte[],%20java.nio.file.OpenOption...))؛ التشغيل على API 31–35 «يُثبت ميدانياً».
- التحقق النهائي للإصلاحات: نجح `./gradlew build test lint koverVerify` محلياً (JDK 17)، بما فيه حد التغطية الأصلي 90% للحارس واختبارات منع اعتماديات الملفات. كل اختبار جديد أُجري قبل الإصلاح وأخفق ثم نجح بعده؛ لم يُعطّل اختبار أو فحص.

- **A-1 — تم:** أُضيف `@Volatile` إلى حالة `GuardTask` ليكون نشر الكتابات مرئياً للقراءات غير المتزامنة، مع إبقاء انتقالات الحالة داخل `@Synchronized`. اختبار `stateIsSafelyPublishedToReadersOnOtherThreads` يفحص عقد النشر في الصنف المترجم ويختبر قارئاً على خيط آخر أثناء إلغاء المهمة؛ فشل قبل الإصلاح.
- **A-2 — تم:** يمرّ إرسال `ERROR_CLIENT` في `AssistantRecognitionService` بمسار داخلي يلتقط `RemoteException` ويسجّل `recognition_client_disconnected` فقط، دون نص الاستثناء أو محتوى التعرف. اختبار `AssistantRecognitionServiceTest` يحاكي مستمعاً منقطعاً وآخر متصلاً، ويتحقق من التسجيل ومن عدم ابتلاع أخطاء أخرى؛ أخفق اختبار الانقطاع قبل الإصلاح. أُضيف Robolectric 4.17 لاختبار JVM في `core/assist` فقط، وهو الإصدار نفسه المعتمد في M3، مع إنشاء مجلد الملفات المؤقتة تلقائياً. التحقق بتاريخ 2026-11-10؛ تعامل Binder على جهاز فعلي «يُثبت ميدانياً».
- تحقق الملحق 1: نجح `./gradlew build test lint koverVerify` محلياً بـJDK 17، بما فيه اختبارات الخدمة في نسختي debug وrelease وحد تغطية الحارس 90%. لم يُعطّل اختبار أو قاعدة lint.
