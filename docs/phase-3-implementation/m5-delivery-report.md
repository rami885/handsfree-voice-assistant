## الإصدارات والأوامر

مصفوفة Android لم تتغير: AGP 9.5.1، Gradle 9.6.0، Kotlin المدمج 2.4.21، KSP 2.3.13، Hilt 2.60.1، Coroutines 1.11.0، Room 2.8.5، Kover 0.9.11، JUnit 4.13.2، AndroidX Test Runner 1.7.0، Espresso المثبت غير المستخدم 3.7.0، minSdk 31 وcompile/target 36 وbuild-tools 36.0.0 وJDK 17.

Node 22.23.4 وnpm 10.9.9؛ TypeScript 6.0.3، Vitest 5.1.0، ESLint 10.14.0، @eslint/js 10.0.1، typescript-eslint 8.72.2، globals 17.14.0، @types/node 22.20.5، Wrangler 4.159.0. package-lock.json ملتزم. لا حزم نظام جديدة.

## قرارات اتخذتها

- تجزئة طلب التسجيل تخص كائن registration الذي يضم nonce وpreviousToken عند التجديد، قبل إنشاء integrityToken، بترميز JSON canonical موثق في README. إدخال الغلاف كله بما فيه الرمز في تجزئته دائري وغير قابل للتنفيذ. البديل اعتماد جسم غير محدد يعرّض العميل والخادم لاختلاف التجزئة.
- حكم Integrity لا يعطينا هنا معرّف جهاز ثابتاً. «لكل حكم» فُسرت كفئة من الحزمة والشهادات وحالة الاعتراف وعلامات الجهاز، لا تجزئة رمز الحكم الكامل المتغير في كل طلب. الفئة قد يشترك فيها مستخدمون شرعيون، لذا الحد متحفظ وقد يضر الإتاحة. البديل مفتاح لكل token يسمح بتجاوز الحد بطلب حكم جديد؛ هوية حساب أو Device Recall تحتاج قراراً لاحقاً خارج الدفعة. السقف العام قائم دائماً.
- التجديد يتطلب حكماً جديداً وتوقيع previousToken صحيحاً، ويحافظ على معرّف Durable Object نفسه، حتى لو انتهى عمر الرمز القديم. البديل رفض تجديد المنتهي وإنشاء هوية جديدة يصفر حصته.
- لا ادعاء لمعاملة موزعة بين الكائنين. الحجزان متتابعان، والتعويض يفكهما قبل الاستدعاء عند الفشل. عمليات التخزين نفسها ذرية، وإيصالات إعادة المحاولة تمنع العد المضاعف. تعطل العامل قد يترك حجزاً محافظاً لا يسمح بتجاوز السقف.
- حد الإدخال بايتات UTF-8 للرسالة الفعلية وsystem prompt مع هامش 1024 توكن؛ والخرج محدود، والأسعار من env بميكرو دولار مع كسور. لا أسعار نموذج مفترضة أو طلبات صور/خادم/caching. اعتماد الحد والأسعار مع النموذج الحقيقي شرط تشغيلي قبل نشر لاحق. البديل تقدير متفائل قد ينفق فوق الحصة.
- البث الكامل بتقرير usage مفهوم يُسوّى فعلياً؛ الانقطاع/إلغاء العميل/usage الغائبة أو غير المفهومة يحتفظ بكامل الحجز. لا نعلن كلفة فعلية غير معلومة أو نعيد الطلب. عند فشل الحفظ ثلاث مرات يبقى الحجز مع settlement_pending؛ تنظيف السجلات القديمة والتسوية التشغيلية بعد التعطل تُراجع قبل النشر.
- استُخدم TypeScript 6.0.3 بدلاً من أحدث إصدار رئيسي 7 لأن مجال peer المنشور لـ typescript-eslint الحالي ينتهي قبل 6.1. لا تغيير لمصفوفة Android المثبتة.
- اختبارات المخزن تحاكي معاملة ذات قفل وتسوية rollback، وتختبر كود AtomicBudget نفسه. لا نسمّي ذلك إثبات تشغيل Cloudflare حياً؛ الحساب والأسرار والنشر خارج المهمة.

## العوائق وما لم يُنفذ والتعارضات

- لا عائق يمنع قبول M5 الآلي محلياً. نجحت npm ci ثم 27 اختباراً ثم TypeScript/ESLint. صُلحت ملاحظة prefer-const واختبرنا رفض previousToken الفارغ، دون تعطيل قاعدة أو اختبار.
- أعاد npm audit عشر إشارات moderate أصلها minimatch 10.2.6 ضمن سلسلة أدوات lint التطويرية، بلا اعتماد npm إنتاجي. اقتراحه الآلي تغييرات رئيسية؛ لم ننفذ override أو خفضاً رئيسياً غير مثبت، ولم نخف النتيجة. التفاصيل في README؛ مراجعة تحديث الأدوات مطلوبة قبل التشغيل الحقيقي، وليست بوابة مطلوبة في الملف.
- لا مفاتيح أو رموز حقيقية أو حساب Cloudflare/Google/مزود في الجلسة؛ لا اختبار حي أو اعتماد فاتورة فعلية ولا نشر. كل أسرار الاختبار مولّدة في الذاكرة أو placeholders ولا تُحفظ كأسرار مستودع.
- لا عميل نموذج في Android، ولا أدوات إنتاجية أو شاشات إعداد نهائية. لم تتغير الوثائق المحمية، ولم يلزم الرجوع إلى v12 أو draft4 لأن ملف التنفيذ يحدد M5؛ لا تعارض جديد مكتشف، ويُقترح توضيح دلالة «لكل حكم Integrity» قبل أي تشغيل عام.
- طلبات السحب مؤجلة إلى Claude وفق تعليمات الحاوية؛ يُدفع الفرع والتقرير فقط. لا إيقاف للحاوية أو جهاز رامي.

مراجع رسمية بتاريخ 2026-11-10: [الطلب القياسي لـ Play Integrity](https://developer.android.com/google/play/integrity/standard)، [معاملات Durable Objects SQLite](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)، [البث وusage لدى Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming). تكامل Android الفعلي «يُثبت ميدانياً».

## حادثة حدود الملفات
