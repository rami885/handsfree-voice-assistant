# تقرير التشغيل الليلي M0 إلى M5

التاريخ: 2026-11-10 (UTC). المستودع rami885/handsfree-voice-assistant. هذا الملف بكامله وصف عربي جاهز لطلب السحب النهائي؛ ينسخه Claude عند فتح المسودة، مع تقارير المعالم للأوصاف الفردية. وفق تعليمات الحاوية لم أفتح أي طلب سحب ولم أدمج أو أدفع إلى main أو أعد كتابة تاريخ. كل الفروع متراكبة ومدفوعة إلى origin. لم يُنشر شيء ولم يُطفأ جهاز أو حاوية.

اكتملت M0–M5 بقبول GitHub الآلي، بما فيه اختبارا محاكي API 36. القبول الميداني منفصل ومؤجل إلى رامي؛ لا توجد نتيجة جهاز حقيقي. هذه هي الحالة النهائية التي تتقدم على عبارات «معلّق عند الدفع» التاريخية داخل تقارير التسليم؛ قسم القبول النهائي في كل تقرير يحدد النتيجة اللاحقة.

## ما أُنجز وما تم التحقق منه

- الهيكل والوحدات وWrapper وCI ومعرفا التطبيقين، مع هياكل المنتج فقط. AGP 9.5.1 وGradle 9.6.0 وKotlin المدمج 2.4.21 وKSP 2.3.13 وHilt 2.60.1 وCoroutines 1.11.0 وRoom 2.8.5 وKover 0.9.11؛ minSdk 31 وcompile/target 36 وBuild Tools 36.0.0 وJDK 17. ثبتت في M0 ولم تتغير في M1–M5؛ [تفاصيل المصفوفة](build-matrix.md).
- الحارس JVM: 14 اختباراً، 118/119 سطراً مغطى = 99.16%، وبوابة 90% تمنع CI. اللقطة الكاملة والمصادر والحقن والأذونات/الموافقة والقفل والإلغاء والتدقيق دون محتوى مختبرة.
- المصنّف JVM: ستة اختبارات تغطي الأوامر الـ23 والقوالب والحفظ الحرفي والأعداد وFakePlanner وإلغاءه. قاعدة منع الشبكة مثبتة سلبياً بحقن gRPC مؤقتاً داخل .cache، ثم البناء العادي ناجح.
- probes يضم شاشات التجارب الـ15 من T1a/T1b/T1c إلى T13، مع Room والأذونات والموافقة في الشاشة وتصدير CSV وJSON. GitHub شغّل اختبار الشاشات في M3؛ وفي M4 شغّل الشاشات والتصدير، وفحص XML أثبت الاسمين المطلوبين دون فشل أو تخطٍ. لم نشغّل محاكياً محلياً؛ assembleAndroidTest نجح محلياً.
- وسيط M5: 27 اختباراً، TypeScript/ESLint ناجحان، npm ci ناجح. اختبارات Google/Messages وDurable Objects تستخدم بدائل محلية دون اتصال حي. Node 22.23.4 وnpm 10.9.9 وTypeScript 6.0.3 وVitest 5.1.0 وWrangler 4.159.0؛ بقية الإصدارات مثبتة في package.json والقفل و[تقرير M5](m5-delivery-report.md).
- فحص الأسرار والتصريحات المحظورة وgit diff --check نجحت. لا مفاتيح API حقيقية ملتزمة، ولا INTERNET في probes ولا مكتبات شبكة في guard/intent/probes. لا اختبارات حُذفت أو عُطلت، ولا baseline أو ignore لتمرير lint. قرار تصحيح warningsAsErrors الذي أضفته في M0 مبيّن صراحةً أدناه للمراجعة.

أمر التحقق النهائي، من جذر المستودع؛ تعديل مسار JDK إلى تثبيت 17 الموجود عند اختلاف البيئة:

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export GRADLE_USER_HOME="$PWD/.cache/gradle"
export ANDROID_USER_HOME="$PWD/.cache/android"
export TMPDIR="$PWD/.cache/tmp"
export JAVA_TOOL_OPTIONS="${JAVA_TOOL_OPTIONS:-} -Djava.io.tmpdir=$PWD/.cache/tmp"
export NPM_CONFIG_CACHE="$PWD/.cache/npm"
mkdir -p "$TMPDIR"
./gradlew build test lint assembleAndroidTest :core:guard:koverVerify
python3 scripts/check-safety.py
(cd backend-proxy && npm ci && npm test && npm run lint)
# With an API 36 emulator, as in GitHub Actions:
./gradlew :probes:connectedDebugAndroidTest
python3 scripts/check-emulator-results.py
```

فحص M5 المحلي الأخير لـ Android نجح خلال 3 ثوانٍ (500 مهمة)، ونجحت سلسلة npm النهائية داخل كاش المستودع. سجلات .cache باقية محلياً ومتجاهلة في Git، وليست دليلاً بديلًا عن روابط CI. التحقق على المحاكي لا يثبت سيارة أو HFP أو مكالمات أو WhatsApp أو مشغلاً فعلياً. كل ادعاء سلوكي عن Android أو إذن أو تطبيق آخر في التقرير بتاريخ 2026-11-10 «يُثبت ميدانياً».

## قرارات اتخذتها

القرارات التالية من تقارير المعالم، بما فيها التفسير والبديل حيث كان الغموض مؤثراً. تعليمات الحاوية قدّمت على تعليمات فتح الطلبات وإيقاف الجهاز: دفع فقط، ثم Claude يفتح المسودات؛ لا shutdown.

### M0

- بدأت محاولة M0 بـ AGP 8.10.1 وGradle 8.14.3 وKotlin 2.1.20 وKSP 2.1.20-2.0.1 وHilt 2.56.2. أثبت lint أن هذه المصفوفة تفشل فحوص تحديث الاعتماديات مع warningsAsErrors. انتقلت قبل تثبيت M0 إلى AGP 9.5.1 وGradle 9.6.0 وKotlin المدمج، مع تحديث المكتبات المبينة أعلاه وإضافة dataExtractionRules. لم أُعطّل قاعدة lint أو أخفض شدتها. هذه كانت مصفوفة أولية قبل تثبيت M0؛ المصفوفة الحالية تستخدم AGP 9 وفق نموذج Kotlin المدمج. تصحيح تفسيري السابق للتحذيرات موضح أدناه.
- واجهات core/assist هياكل غير مسجلة في manifest المنتج بعد، وخدمة التعرف فيه ترفض الطلب بوضوح؛ الوكيل الفعلي للتجارب يُنفذ في M3. البديل إضافة سلوك منتج الآن يتجاوز نطاق الهياكل.
- لا Compose قبل وجود شاشة إعداد ضمن النطاق. شاشات التجارب تشخيصية وليست إعداد المنتج النهائي.
- يبدأ backend.yml بفحص الأسرار فقط؛ تضاف أوامر Node واختبارات الوسيط مع كوده في M5، بلا مهمة اختبار معطّلة.
- استخدام JDK 17 المثبت بدلاً من JAVA_HOME الافتراضي الذي يشير إلى JDK 21. كاش Gradle والملفات المؤقتة داخل المستودع، ولم تُثبت حزم نظام.
- تشغيل CI عند دفع كل فرع إضافة إلى طلب السحب، لأن تعليمات الحاوية تؤجل فتح الطلبات إلى Claude.

وصلت المحاولة 11 إلى lint، وانتهى عائق تنزيل Groovy. الفشلان المتبقيان هما OldTargetApi وGradleDependency لأن SDK 37 أحدث من SDK 36 الملزم في الملف. سبب تحويلهما إلى خطأ هو `warningsAsErrors=true` الذي أضفته أنا، ولم يطلبه الملف. أزلت التصعيد العالمي الذي أضفته، وأبقيت `abortOnError=true` وكل قواعد lint بشدتها الأصلية، بلا disable أو ignore أو baseline أو تعديل شدة قاعدة مفردة. ستظل توصية SDK 37 ظاهرة كتحذير، بينما تظل أخطاء lint وفحوص الأذونات المحظورة مانعة للبناء. البديل تغيير SDK إلى 37 يخالف المصدر الملزم، وتعطيل القاعدتين يخالف قواعد المستخدم؛ لم أفعلهما. هذا تصحيح لإعداد أولي زائد، وليس ادعاء أن SDK 36 أحدث إصدار. يجب على المراجعين التحقق من هذا القرار.

### M1

- غياب مصدر الأداة أو أي حقل يحدد المستلم يُرفض، بدلاً من افتراض أن المصدر موثوق. يشمل ذلك recipientLabel وconversationTarget كي لا تمر تعليمات مجموعة كبيانات شكلية.
- الاقتباس غير الموثوق مسموح في PERSONAL_READ فقط؛ لا يعاد توظيفه كنص إرسال أو مستلم أو أداة، وفق قيد الملف.
- كل SEND وCALL_OUT يحتاج تأكيداً حتى إن أخطأ تعريف الأداة وجعل sensitivity=NONE؛ الأفعال المحظورة تبقى مرفوضة أيضاً عند خطأ وسمها.
- نص التأكيد يذكر الفعل والمستلم والمحتوى والوجهة المتاحة؛ اللقطة الكاملة تربط بقية الحقول ومنها الاشتراك وفعل RemoteInput. لا يسجّل السجل هذا النص.
- خريطة المصادر تُنسخ إلى خريطة غير قابلة للتعديل، لأن val وحده لا يمنع تعديل خريطة قدمها المستدعي بعد التأكيد.
- لا تُلغى عملية بدأت Executing بأثر رجعي؛ cancel ينجح قبلها فقط كما يطلب الملف. يحتاج الربط الإنتاجي لاحقاً إيقاف المهام التي يمكن إيقافها عند Stop أو قفل الشاشة. لا توجد أداة إنتاجية هنا.
- سجل التدقيق ملف محلي بسيط بمخطط ثابت من بيانات القرار؛ أسماء الأدوات معرفات ثابتة لا تقبل أرقاماً. السبب رمز محدد، وليس رسالة استثناء أو نصاً من المستخدم. البديل Room داخل الحارس يخالف كونه وحدة JVM خالصة.

### M2

- نص الملاحظات وتعديل الرسالة بيانات حتى لو احتوى أسماء أو أوامر متعددة، لأن مثال الملف يتطلب حفظ `Call Nikos, 5 p.m.`. أما الأوامر التنفيذية التي تطلب مستلماً مسمى أو خطوات متعددة فتعيد null. البديل رفض الأسماء داخل متن الملاحظة يناقض المثال الملزم.
- تُستهلك مسافة فصل واحدة بعد النقطتين أو كلمة to كجزء من صيغة الأمر؛ كل ما يليها يُحفظ حرفياً، بما فيه المسافات الإضافية والأسطر والترقيم. لا trim لمتن النص. النص الفارغ أو المكون من مسافات فقط غير مطابق.
- القيم العددية تعاد كنص عددي ذي معنى، بينما متن النص لا يمر بالتطبيع مطلقاً. الأعداد الإنجليزية تدعم الوحدات والعشرات والمئات والآلاف والكسر المنطوق رقماً رقماً. لا تُخمن الصيغ غير المكتملة أو الكسور من نوع .5، ولا تحوّل سالباً إلى موجب عند إزالة الترقيم؛ تعود إلى المخطط الوهمي لاحقاً عبر null.
- علامات الترقيم الفاصلة تتحول إلى فراغات في المطابقة لمنع دمج `1,5` إلى `15`. النقطة بين رقمين تبقى نقطة عشرية. الفاصلة العليا في What's تُزال ليتطابق القاموس.
- قاعدة الشبكة تشمل guard وintent وprobes، وتشمل classpaths الاختبار أيضاً. في وحدتي JVM توجد قائمة مجموعات معروفة محدودة، إضافة إلى منع أسماء مكتبات النقل الشائعة؛ إضافة مجموعة جديدة تتطلب مراجعة التغيير في القاعدة. أدوات بناء Gradle نفسها ليست اعتماديات تطبيق ولا تُفحص كعميل إنتاجي.
- FakePlanner يعيد نتيجة اختبار جاهزة، ويدعم تأخيراً قابلاً لإلغاء coroutine، ولا يحتفظ بنص الطلب أو يسجله. لا يوجد ClaudePlanner أو API للنموذج.

### M3

- واجهات التجارب Android Views تشخيصية، وليست شاشات إعداد نهائية؛ لذلك لا Compose خارج غرضه المحدد. Hilt يحقن حاوية التطبيق، وRoom مستقل عن وحدتي JVM.
- عميل T1a يستخدم المصنع الافتراضي عمداً لقياس مروره بالوكيل؛ الوكيل يستهدف خدمة Google المعلنة عبر PackageManager، دون افتراض اسم صنف داخلي أو الرجوع إلى نفسه. بقية التعرف تستخدم on-device إن توفر، وإلا Google الصريح مع تسجيل ذلك. لا يُعلن أن المسار محلي عند استخدام المصنع الآخر.
- واجهة Callback الرسمية لا تعرض onEvent نظيراً لكل حدث RecognitionListener؛ الأحداث الإضافية تسجل كرموز، بينما تُمرر callbacks المتاحة للجاهزية والكلام والنتائج الجزئية والنهائية والأخطاء والتجزئة المدعومة. لا انعكاس أو واجهة مخفية لاستحداث callback غير موجودة.
- T1b لا يقرأ جهة محفوظة إلا مع موافقة Contacts وإذنها معاً. لقياس حالة عدم READ_CONTACTS فعلياً، يرفض رامي الإذن من إعدادات التطبيق؛ إلغاء الموافقة الداخلية وحده لا يسحب إذن النظام. لا يمنع غياب Contacts التجربة نفسها: يكون الإعلان عاماً.
- انتظار onShow يسبق الصوت في T1b، وcallback الجهاز يسبق أي اسم خاص. يُضبط TTS على USAGE_VOICE_COMMUNICATION، ويُفحص المسار مجدداً قبل النطق؛ فقدانه يوقف النطق والتعرف ولا يختار مكبر الهاتف تلقائياً.
- لا يُفترض إغلاق الميكروفون الفيزيائي لمجرد cancel/destroy؛ السجل يفصل wasListening وclientClosed وزمن الطلب، ويضع physicalMicClosure=manual_validation_required. رامي يراجع المؤشر والصوت على الجهاز.
- الاتصال في T2 مربوط بلقطة Guard، وموافقة CALL_PHONE مستقلة، وجهة محفوظة عند القفل ما لم يُفعّل المفتاح، وحساب PhoneAccountHandle ثابت يُعاد التحقق من وجوده. لا نخمن subscriptionId من فهرس الحساب؛ EXTRA_PHONE_ACCOUNT_HANDLE يحمل الحساب المختار فعلياً.
- كلمات T2 التشخيصية تأتي من صوت المستخدم في الجلسة؛ نص الإشعارات لا يدخل هذا المسار. Stop/Cancel والأزرار وقفل الشاشة تلغي المهام المنتظرة. طلب جديد صريح من جلسة المساعد بعد إطفاء الشاشة يبدأ تجربة جديدة؛ لا مؤقت إطلاق خفي يتجاوز الإلغاء.
- Start في T3 يؤخر البدء خمس ثوانٍ ليتاح وضع تطبيق آخر في المقدمة. لا يُتجاوز رفض النظام. T8 التي تقيس أثناء مكالمة نشطة تضاف في M4؛ ليست ميزة أوامر أثناء المكالمة.
- إحصاء SCO يذكر عدد النتائج المؤكدة من 20 ولا يخترع قياسات للمهلات. p90 بالرتبة الأقرب للأعلى، والوسيط متوسط القيمتين الوسطيتين عند العدد الزوجي.
- Stop في T13 يوقف الجملة الحالية ويُحسب ضمن سلسلة التجارب العشرين؛ زر Stop/Cancel يوقف السلسلة كلها. هذا قياس barge-in تشخيصي، وليس وكيلاً إنتاجياً يستمر بعد الإلغاء.
- سير المحاكي يستخدم reactivecircus/android-emulator-runner@v2 وAPI 36. تهيئة KVM في آلة GitHub المؤقتة حسب تعليمات الإجراء؛ لم تُشغّل أو تُثبت محاكيات أو حزم نظام في الحاوية المحلية.

### M4

- T5 لا يستنتج تعليمات من النص؛ المصدر الوحيد لإرسال Answer/Decline هو زر المستخدم أو كلمته في الجلسة الحالية. Start يسلّح التجربة، وStop أو تغيير الموافقة يزيل التسليح. الفعل يطابق العنوان الإنجليزي المحدد، وحزمة منشئ PendingIntent يجب أن تكون com.whatsapp؛ أي غياب أو تغير يُسجل. لا ضمان جواب فعلي لمجرد نجاح send؛ ملاحظة رامي هي نتيجة المكالمة.
- استعمال جلسة المساعد في T5 يجعل اختبار PIN ممكناً من التطبيق نفسه دون ADB أو نشاط إعداد فوق القفل. الميكروفون وحالة الهاتف اختياريان للفرع الصوتي؛ الأزرار لا تحتاج تعرفاً. لا استماع عند OFFHOOK أو وضع اتصال، حتى في فرع WhatsApp.
- الوصول إلى الجلسة في T6 عبر Notification.EXTRA_MEDIA_SESSION العام، بدلاً من صلاحية MEDIA_CONTENT_CONTROL النظامية. الواجهة الحالية لا تفحص جلسات لا تعلن Token في إشعارها، وتسجل ذلك صراحةً. نية البحث المستقلة تعمل بلا وصول إشعارات، بينما فرع MediaController يتطلب الموافقة والوصول.
- الحالة الباردة لا تُفرض بقتل تطبيق آخر؛ المختبر يغلق المشغل على الهاتف ويحدد الحالة. أول callback metadata قد يحمل عنواناً سابقاً في الحالة النشطة؛ يُسجل وجود metadata الأساس ولا يُعد هذا وحده إثبات نجاح البحث. titleContainsQuery مؤشر نصي، والمطابقة الفعلية خانة يراجعها المختبر.
- القراءة الشخصية لعناوين الوسائط تُحجب فوق القفل ما لم يسمح المفتاح. أسماء المتصلين المنطوقة مؤقتة على الشاشة ولا تدخل تاريخها؛ بيانات الجلسة القديمة تُحجب فوق القفل. لا نطق تلقائي لمحتوى رسائل في هذه الدفعة.
- T11 يبدأ سلبياً كي لا يغيّر المقارنة؛ الوضع النشط اختياري وموسوم بأنه يغير توجيه الأزرار. المصدر receiver أو session مسجل لتمييز التكرارات المحتملة. «رد/استدعى المساعد/لا شيء» ملاحظة ميدانية، مع أحداث الخدمة وحالة المكالمة إن أُذن بها.
- التصدير يأخذ SELECT واحداً ثم يبني الملفين من القائمة نفسها، ولا يقتصر على آخر 200 صف المعروضة في الواجهة. تُنشر الملفات بعد الكتابة وتُحذف الملفات المنشأة في العملية نفسها عند خطأ/إلغاء. ليست هذه معاملة ذرية عامة عبر MediaStore؛ لا يُدعى ذلك.
- إلغاء موافقة حساسة يوقف التجربة فوراً ويزيلها من الحالة الحالية. قفل الشاشة يلغي طلب التصدير الجاري قبل إكمال نشره. لا أذونات جديدة خارج manifest المرجعي؛ أضيفت فقط رؤية حزمتَي WhatsApp وGboard للاختبار ونسخهما، دون QUERY_ALL_PACKAGES.
- أُغلق مصدر PCM الخاص بـ T13 أيضاً عند المقاطعة فوراً، وأصبح close متكرراً بأمان، بدلاً من انتظار عودة دالة التعرف. ومنعنا رسالة «لا أسمعك» بعد تغير حالة المكالمة أو فقدان المسار. هذا تصحيح أمان مشترك ضمن الفرع النهائي M4؛ ينبغي أن تتناول المراجعة الثلاثية هذا التصحيح عند تقييم M3 أيضاً قبل الدمج.
- أُضيف فحص XML لأسماء الاختبارين وعدد نجاحهما حتى لا يُستنتج تنفيذهما من build ناجح وحده. لا Ignore أو baseline أو مسار تخطٍ للاختبار.

### M5

- تجزئة طلب التسجيل تخص كائن registration الذي يضم nonce وpreviousToken عند التجديد، قبل إنشاء integrityToken، بترميز JSON canonical موثق في README. إدخال الغلاف كله بما فيه الرمز في تجزئته دائري وغير قابل للتنفيذ. البديل اعتماد جسم غير محدد يعرّض العميل والخادم لاختلاف التجزئة.
- حكم Integrity لا يعطينا هنا معرّف جهاز ثابتاً. «لكل حكم» فُسرت كفئة من الحزمة والشهادات وحالة الاعتراف وعلامات الجهاز، لا تجزئة رمز الحكم الكامل المتغير في كل طلب. الفئة قد يشترك فيها مستخدمون شرعيون، لذا الحد متحفظ وقد يضر الإتاحة. البديل مفتاح لكل token يسمح بتجاوز الحد بطلب حكم جديد؛ هوية حساب أو Device Recall تحتاج قراراً لاحقاً خارج الدفعة. السقف العام قائم دائماً.
- التجديد يتطلب حكماً جديداً وتوقيع previousToken صحيحاً، ويحافظ على معرّف Durable Object نفسه، حتى لو انتهى عمر الرمز القديم. البديل رفض تجديد المنتهي وإنشاء هوية جديدة يصفر حصته.
- لا ادعاء لمعاملة موزعة بين الكائنين. الحجزان متتابعان، والتعويض يفكهما قبل الاستدعاء عند الفشل. عمليات التخزين نفسها ذرية، وإيصالات إعادة المحاولة تمنع العد المضاعف. تعطل العامل قد يترك حجزاً محافظاً لا يسمح بتجاوز السقف.
- حد الإدخال بايتات UTF-8 للرسالة الفعلية وsystem prompt مع هامش 1024 توكن؛ والخرج محدود، والأسعار من env بميكرو دولار مع كسور. لا أسعار نموذج مفترضة أو طلبات صور/خادم/caching. اعتماد الحد والأسعار مع النموذج الحقيقي شرط تشغيلي قبل نشر لاحق. البديل تقدير متفائل قد ينفق فوق الحصة.
- البث الكامل بتقرير usage مفهوم يُسوّى فعلياً؛ الانقطاع/إلغاء العميل/usage الغائبة أو غير المفهومة يحتفظ بكامل الحجز. لا نعلن كلفة فعلية غير معلومة أو نعيد الطلب. عند فشل الحفظ ثلاث مرات يبقى الحجز مع settlement_pending؛ تنظيف السجلات القديمة والتسوية التشغيلية بعد التعطل تُراجع قبل النشر.
- استُخدم TypeScript 6.0.3 بدلاً من أحدث إصدار رئيسي 7 لأن مجال peer المنشور لـ typescript-eslint الحالي ينتهي قبل 6.1. لا تغيير لمصفوفة Android المثبتة.
- اختبارات المخزن تحاكي معاملة ذات قفل وتسوية rollback، وتختبر كود AtomicBudget نفسه. لا نسمّي ذلك إثبات تشغيل Cloudflare حياً؛ الحساب والأسرار والنشر خارج المهمة.

## ما يفعله رامي على الأجهزة بعد اكتمال M4

هذه خطة قبول ميداني مأخوذة من ملف التنفيذ، وليست نتائج تجارب منفذة. تاريخ إعدادها 2026-11-10. جميع السلوكيات والأذونات المذكورة «يُثبت ميدانياً». لا تبدأ قبل وجود APK التجارب المكتمل واختبار فتح الشاشات وتصدير النتائج؛ APK هيكل M0 لا يشغّل هذه التجارب.

1. جهّز أجهزة Android 16 و14 و12 أو 13، وجهازاً لجولة Android 15؛ سجّل الطراز والإصدار والتحديث الأمني. جهّز شريحة ثانية وسماعة HFP والسيارة، وهاتفاً آخر لإجراء المكالمات التجريبية. احسم منفصلاً مسألة Spotify قبل أي انتقال للمسار الإنتاجي للوسائط.
2. افتح تشغيل Android الناجح لـ M5 من الجدول أعلاه ونزّل القطعة `probes-apk`، ثم ثبّت APK الخاص بـ `com.handsfree.probes` منها. بديل مطابق لكود التطبيق هو قطعة M4 الناجحة المشار إليها في الجدول، لأن M5 لا يغير Android. راجع اسم الحزمة والإصدار. افتح قائمة التجارب؛ لا تمنح الأذونات دفعة واحدة. في كل تجربة سجّل حالتها قبل الأذونات وبعدها، واحتفظ بنتيجة «إذن مرفوض» عند الرفض.
3. اتبع خطوات كل تجربة أدناه على الأجهزة المحددة، مع تكرار الحالات الباردة والنشطة والقفل حيث يلزم. لا تحوّل فشل تجربة أو غياب تطبيق إلى نجاح؛ دوّن «غير مدعوم هنا» مع السبب.
4. بعد كل مجموعة صدّر CSV وJSON إلى `Downloads/probes/`، وتأكد من وجود الأحداث والوقت والطراز وSDK وإصدارات التطبيقات. ارفع النسخ التي راجعتها إلى `docs/experiments/`، ثم تُكتب وثيقة قرار التجارب قبل M6.

## أسئلة المراجعة الصباحية لـ Claude وCodex وGemini

1. هل قواعد Guard المغلقة والمصادر المطلوبة ونسخ snapshot تمنع حقن الرسالة/المجموعة، وهل تأكيد كل SEND/CALL_OUT حتى مع حساسية خاطئة هو التفسير المقبول؟ راجعوا كل حقل والتغير بعد التأكيد والإلغاء قبل Executing.
2. هل حفظ متن الملاحظة بعد مسافة الصيغة الواحدة، ورفض .5 والأرقام السالبة والصيغ غير المكتملة، يحقق نية التطبيع دون فقد النص؟ هل تتطلب الصيغ حالات إضافية قبل المنتج؟
3. هل تقبلون تصحيح warningsAsErrors الزائد في M0 مع جميع قواعد lint بشدتها الأصلية وSDK 36 الملزم، أم يلزم حسمه صراحةً قبل الدمج؟ لا يُرفع SDK أو تُعطل قاعدة لإخفاء التعارض.
4. راجعوا توقف الصوت/التعرف فور فقد المسار أو الموافقة أو تغير حالة المكالمة/الدور، وبخاصة تصحيح إغلاق PCM الخاص بـ T13 الذي وصل في M4. يجب مراجعة M3 ضمن الحالة المتراكبة المصححة قبل الدمج.
5. هل مسار T2/T10 من جلسة حقيقية فوق القفل، وحساب PhoneAccountHandle الثابت، ومراقبة الشرائح كافية لصلاحية التجربة؟ لا يمكن حسم ذلك دون نتائج رامي لكل جهاز. هل جميع خطوات الواجهة مفهومة قبل الجولة؟
6. راجعوا قيد T6 الذي يقرأ Token معلناً في إشعار الوسائط، والمقارنة الباردة/النشطة ومطابقة metadata اليدوية. لا تعني التجربة اعتماد Spotify أو المسار الإنتاجي 2؛ من يحسم السياسة القانونية قبل M6؟
7. هل فئة أحكام Integrity المشتركة تحقق نية حد إعادة إنشاء الهوية؟ يلزم حسم الإتاحة وحد الفئة أو هوية إضافية لاحقاً، دون الادعاء بامتلاك معرّف جهاز ثابت. راجعوا canonical registration وربط previousToken وصلاحية 30 يوماً.
8. قبل نشر لاحق: هل حد بايتات الإدخال مع هامش 1024 والأسعار المختارة للنموذج محافظ بما يكفي؟ من يثبت ذلك مع فاتورة فعلية؟ راجعوا احتساب الحجز كاملاً عند انقطاع البث، والحجوزات العالقة والتعويض بين الكائنين وخطة تنظيف الأيام القديمة. لا يوجد نشر معتمد الآن.
9. هل يكفي مخزن المعاملات البديل لإثبات قبول المنطق في M5، وما تجربة runtime اللازمة لاحقاً على Cloudflare؟ هل تحديث minimatch/ESLint وchecksum Wrapper مطلوبان كمتابعة قبل تشغيل عام؟
10. تحققوا من مخالفتي الكتابة خارج المستودع المذكورتين، وافصلوا ذلك عن نجاح الكود وCI؛ لا تُعرض الجلسة كامتثال كامل. لا أسرار API حقيقية ملتزمة.
11. أين حكما الدمج لمراجعتي v12 وdraft4، ومن يكتب وثيقة قرار التجارب والنسخة 13/المسودة 5 بعد ملفات رامي؟ لم تُعدل الوثائق المحمية أو تُكتب مراجعة مستقلة بدلاً من المراجعين.

لا أدوات tools-* إنتاجية ولا إعداد نهائي ولا ClaudePlanner شبكي ولا MCP أو Accessibility أو واجهات مخفية. الخطوة التالية: Claude يفتح المسودات المتراكبة وينسخ هذا التقرير كاملاً في وصف الطلب النهائي، ثم المراجعة الثلاثية وحكم الدمج، ورامي ينفذ الجولة الميدانية. M6 ينتظر وثيقة قرار التجارب والحسم القانوني للوسائط.
