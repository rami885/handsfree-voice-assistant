## الإصدارات والأوامر

لم تتغير المصفوفة عن M0: AGP 9.5.1، Gradle 9.6.0، Kotlin 2.4.21، KSP 2.3.13، Hilt 2.60.1، Coroutines 1.11.0، Room 2.8.5 (المخطط ما زال الإصدار 1)، Kover 0.9.11، JUnit 4.13.2، AndroidX Test Runner 1.7.0، Espresso المثبت 3.7.0 غير المستخدم هنا. Node 22.23.4 وnpm 10.9.9 في الحاوية، ولا وسيط بعد.

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export GRADLE_USER_HOME="$PWD/.cache/gradle"
export ANDROID_USER_HOME="$PWD/.cache/android"
export TMPDIR="$PWD/.cache/tmp"
./gradlew build test lint assembleAndroidTest :core:guard:koverVerify
# With an API 36 emulator:
./gradlew :probes:connectedDebugAndroidTest
python3 scripts/check-emulator-results.py
```

من الشاشة الرئيسية أو شاشة أي تجربة: Export CSV and JSON، ثم Files > Downloads > probes. تظهر نتيجة العملية في الحالة. لا يلزم طلب إذن تخزين عام في الكود؛ سلوك MediaStore على الأجهزة «يُثبت ميدانياً».

## قرارات اتخذتها

- T5 لا يستنتج تعليمات من النص؛ المصدر الوحيد لإرسال Answer/Decline هو زر المستخدم أو كلمته في الجلسة الحالية. Start يسلّح التجربة، وStop أو تغيير الموافقة يزيل التسليح. الفعل يطابق العنوان الإنجليزي المحدد، وحزمة منشئ PendingIntent يجب أن تكون com.whatsapp؛ أي غياب أو تغير يُسجل. لا ضمان جواب فعلي لمجرد نجاح send؛ ملاحظة رامي هي نتيجة المكالمة.
- استعمال جلسة المساعد في T5 يجعل اختبار PIN ممكناً من التطبيق نفسه دون ADB أو نشاط إعداد فوق القفل. الميكروفون وحالة الهاتف اختياريان للفرع الصوتي؛ الأزرار لا تحتاج تعرفاً. لا استماع عند OFFHOOK أو وضع اتصال، حتى في فرع WhatsApp.
- الوصول إلى الجلسة في T6 عبر Notification.EXTRA_MEDIA_SESSION العام، بدلاً من صلاحية MEDIA_CONTENT_CONTROL النظامية. الواجهة الحالية لا تفحص جلسات لا تعلن Token في إشعارها، وتسجل ذلك صراحةً. نية البحث المستقلة تعمل بلا وصول إشعارات، بينما فرع MediaController يتطلب الموافقة والوصول.
- الحالة الباردة لا تُفرض بقتل تطبيق آخر؛ المختبر يغلق المشغل على الهاتف ويحدد الحالة. أول callback metadata قد يحمل عنواناً سابقاً في الحالة النشطة؛ يُسجل وجود metadata الأساس ولا يُعد هذا وحده إثبات نجاح البحث. titleContainsQuery مؤشر نصي، والمطابقة الفعلية خانة يراجعها المختبر.
- القراءة الشخصية لعناوين الوسائط تُحجب فوق القفل ما لم يسمح المفتاح. أسماء المتصلين المنطوقة مؤقتة على الشاشة ولا تدخل تاريخها؛ بيانات الجلسة القديمة تُحجب فوق القفل. لا نطق تلقائي لمحتوى رسائل في هذه الدفعة.
- T11 يبدأ سلبياً كي لا يغيّر المقارنة؛ الوضع النشط اختياري وموسوم بأنه يغير توجيه الأزرار. المصدر receiver أو session مسجل لتمييز التكرارات المحتملة. «رد/استدعى المساعد/لا شيء» ملاحظة ميدانية، مع أحداث الخدمة وحالة المكالمة إن أُذن بها.
- التصدير يأخذ SELECT واحداً ثم يبني الملفين من القائمة نفسها، ولا يقتصر على آخر 200 صف المعروضة في الواجهة. تُنشر الملفات بعد الكتابة وتُحذف الملفات المنشأة في العملية نفسها عند خطأ/إلغاء. ليست هذه معاملة ذرية عامة عبر MediaStore؛ لا يُدعى ذلك.
- إلغاء موافقة حساسة يوقف التجربة فوراً ويزيلها من الحالة الحالية. قفل الشاشة يلغي طلب التصدير الجاري قبل إكمال نشره. لا أذونات جديدة خارج manifest المرجعي؛ أضيفت فقط رؤية حزمتَي WhatsApp وGboard للاختبار ونسخهما، دون QUERY_ALL_PACKAGES.
- أُغلق مصدر PCM الخاص بـ T13 أيضاً عند المقاطعة فوراً، وأصبح close متكرراً بأمان، بدلاً من انتظار عودة دالة التعرف. ومنعنا رسالة «لا أسمعك» بعد تغير حالة المكالمة أو فقدان المسار. هذا تصحيح أمان مشترك ضمن الفرع النهائي M4؛ ينبغي أن تتناول المراجعة الثلاثية هذا التصحيح عند تقييم M3 أيضاً قبل الدمج.
- أُضيف فحص XML لأسماء الاختبارين وعدد نجاحهما حتى لا يُستنتج تنفيذهما من build ناجح وحده. لا Ignore أو baseline أو مسار تخطٍ للاختبار.

## العوائق وما لم يُنفذ والتعارضات

- لا محاكي محلي؛ compile/assemble نجح، والتنفيذ الفعلي للاختبارين ينتظر GitHub. لا نتائج سيارة أو سماعة أو مكالمة حقيقية أو WhatsApp/مشغل حقيقي في هذه الحاوية.
- محاولة قراءة ZIP تقرير M3 محلياً عبر رابط الملف الموقّع أعادت HTTP 403 ثلاث مرات، مع فاصلَي 10 و20 ثانية. جرى التحقق من حالة مهمة المحاكي وسجل أمر connectedDebugAndroidTest مباشرة عبر GitHub وكانا ناجحين؛ تعذر تنزيل النسخة لا يعني فشل CI. المراجع يستطيع فتح التقرير في GitHub. أضيفت ملفات XML نفسها ونتيجة فحصها إلى CI الحالي لتسهيل التدقيق.
- لا عائق بناء محلي باقٍ في M4، ولم تُثبت حزم نظام أو تتغير المصفوفة. لا أدوات إنتاجية أو RemoteInput أو SMS أو تخطيط متصل أو نشر. تجارب المشغلات لا تعتمد المسار الإنتاجي 2 أو تحسم سياسة Spotify.
- لم تُعدّل الوثائق المحمية؛ لا تعارض جديد مكتشف مع v12 أو draft4، ولم يلزم الرجوع إليهما لأن الملف يحدد هذه التجارب. كل استنتاج عن أذونات أو سلوك Android/التطبيقات على الأجهزة بتاريخ 2026-11-10 «يُثبت ميدانياً».

مراجع الواجهات العامة: [NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService)، [Notification.EXTRA_MEDIA_SESSION](https://developer.android.com/reference/android/app/Notification#EXTRA_MEDIA_SESSION)، [MediaStore](https://developer.android.com/training/data-storage/shared/media#downloads).
